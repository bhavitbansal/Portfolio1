Project Overview

The Browser Arcade Game was created to demonstrate how immersive interactive games can be constructed directly in the DOM using Vanilla JavaScript and HTML5 Canvas API without relying on third-party frameworks like Phaser or PixiJS.

By leveraging native web technologies, the game maintains a minimal bundle footprint while delivering crisp visuals, responsive controls, continuous state rendering, and local high-score management.

Problem Statement

Web-based games built without dedicated game engines often struggle with two critical execution challenges: frame-rate stutter caused by garbage collection pauses during object allocation, and inconsistent velocity physics across displays with varying refresh rates (60Hz vs 120Hz vs 144Hz screens).

The objective was to design a clean, zero-dependency JavaScript game loop that maintains frame-rate independent entity physics and sub-pixel spatial hit detection across desktop, tablet, and mobile browsers.

Solution

To eliminate garbage collection pauses, the game implements an Object Pooling pattern for active game entities (projectiles, particle FX, dynamic obstacles). Object instances are instantiated at launch and recycled during render cycles rather than created and destroyed on the fly.

To achieve display-agnostic physics, movement speed calculations utilize a delta-time factor evaluated on every requestAnimationFrame loop tick, guaranteeing identical gameplay speeds regardless of display refresh rate.

Technologies Used

HTML5 Canvas API CSS3 Animations Vanilla JavaScript (ES6+) Object Pooling Pattern AABB Collision Physics LocalStorage State Management

Challenges & Engineering Solutions

Collision Accuracy under High Speeds: At accelerated game difficulty curves, fast-moving entities occasionally skipped through hitboxes between frame ticks (tunneling effect). This was solved by applying swept Axis-Aligned Bounding Box (AABB) checks, evaluating sub-step line segments to ensure zero missed collisions.

Mobile Touch Input Responsiveness: Touch inputs on mobile screens caused default browser scroll and zoom gestures. Applying passive touch event listeners with targeted preventDefault() handlers yielded instantaneous mobile control response.

What I Learned

Engineering a browser-native game engine deepened my mastery of the JavaScript event loop, execution scoping, memory allocation lifecycle, and HTML5 Canvas rendering mechanics.

It reinforced the engineering mindset of evaluating underlying browser primitives before reaching for heavy external library dependencies.
